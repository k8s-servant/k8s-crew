# k8s-crew v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship k8s-crew v1: a triage crew where a boss agent splits a Kubernetes problem across read-only helper agents (subagents in Claude Code or Copilot CLI, or herdr panes) built on k8s-skills, proven by scored multi-fault kind scenarios.

**Architecture:** The product is Markdown (a boss skill, a vendor-neutral recipe and investigator role, runner notes, agent definitions) plus config examples and RBAC YAML. Python tooling (pytest, like k8s-skills) does static checks, transcript tier checks and report-shape checks, reusing k8s-skills' command checker from a pinned release. Bash scripts build the kind test cluster, break scenarios, run the crew or a single-agent baseline non-interactively, and score the result.

**Tech Stack:** Markdown skills (Agent Skills format), Claude Code subagents, Copilot CLI custom agents, herdr CLI, Python 3.12 + pytest + ruff, Bash, kind, kubectl, release-please.

**Spec:** `docs/superpowers/specs/2026-11-09-k8s-crew-v1-design.md`

## Global Constraints

- License Apache-2.0. Conventional Commits. release-please owns versions and `CHANGELOG.md`; never edit them by hand. No attribution lines in commits.
- Placeholders only (`my-namespace`, `my-app`, `example.com`). No real cluster names, registries, hostnames, tenant IDs, company names or personal data.
- Never read Secrets in any command, script, example, test or prompt.
- Never copy a k8s-skills skill. Depend on it. Copying scripts from k8s-skills is fine.
- k8s-skills pin: `K8S_SKILLS_REF=v0.10.0` in `tests/versions.env`. The command allow-list and checker come from that ref, fetched into `.cache/k8s-skills-<ref>/` (git-ignored).
- The crew session only ever has the view-only identity. The crew never runs a fix; it prints each fix with an `# Undo:` line for the user to run.
- Helpers: default 3, max 4 (Claude Code subagents and herdr); Copilot CLI subagent mode default 2.
- Test cluster name `k8s-crew-test`, context `kind-k8s-crew-test`. Scripts refuse to run against any other context.
- Report sections, exact headings in this order: `## Root cause`, `## Knock-on effects`, `## Separate issues`, `## Fixes`, `## What was checked`, `## Helper details`.
- Investigator finding sections, exact headings: `### Finding`, `### Evidence`, `### Confidence` (one of `confirmed`, `likely`, `not sure`), `### Proposed fixes`.
- Scenario runs are not part of PR CI. PR CI: ruff, pytest, markdown lint, `python -m tools.crewcheck check`.
- Creating the GitHub repo `k8s-servant/k8s-crew`, pushing, and publishing need the author's explicit go-ahead at that moment.

## Review Focus

1. **Agent chains commands** (`kubectl get pods -A && kubectl get nodes`, pipes to `grep`): the transcript tier check must split on `&&`, `||`, `;` and newlines and judge each piece, not fail every compound line. Test in Task 3.
2. **Session started with an admin kubeconfig**: the boss must stop before starting helpers and explain how to switch to the viewer. Test in Task 5 (pre-check script) with a fake `kubectl auth can-i` that answers `yes`.
3. **Clean cluster**: no helpers started, no invented issues, the report says what was checked. Pinned by the `healthy-noise` scenario (Task 8) and a report-shape test where all issue sections say "None" (Task 4).
4. **Copilot answers before herdr sees it working** (`agent_prompt_stalled`): herdr runner must read the pane, never resend. Pinned in the herdr runner text and a crewcheck rule (Task 6).
5. **Investigator definition not installed**: boss refuses subagent mode and names `scripts/install-agents.sh`; never falls back to a generic subagent. Test in Task 5 (pre-check) and the install script test (Task 5).
